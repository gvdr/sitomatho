# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AI SLOP ("AI Studies in Laboriously Obtained Proofs") is a parody journal. The theorems are real: each one is generated by a Lean 4 metaprogram and checked by the Lean kernel against a pinned Mathlib. Everything around them (titles, invented AI model attributions, referee reports, importance scores, press releases) is satire produced by an LLM editorial desk. The site is deployed with GitHub Pages at https://sitomatho.gvdallariva.net/ from `github.com/gvdr/sitomatho`.

`AGENTS.md` holds the coding style, naming, and commit conventions. Read it alongside this file.

## Commands

`lake` is installed under `~/.elan/bin` and may be missing from `PATH`. The Python scripts locate it themselves (`find_lake` in `scripts/verify.py`); for direct Lake commands use `~/.elan/bin/lake` or export the directory first.

```bash
# Lean side
lake exe cache get                 # prebuilt Mathlib oleans, needed before anything else
lake build Babel Corpus walk       # generator library, curated corpus, and the walk executable
lake build BabelTest               # Lean checks in Babel/Tests.lean; a failing #guard fails the build

# Python side (local venv is .venv/, CI uses Python 3.12; the only dependency is Jinja2)
.venv/bin/python scripts/test_akcm.py                      # whole test suite, no Lean or network needed
.venv/bin/python -c "import sys; sys.path.insert(0, 'scripts'); import test_akcm; test_akcm.test_blocklist()"   # one test
.venv/bin/python scripts/verify.py                         # kernel-check every results/*/Result.lean (slow)
.venv/bin/python scripts/verify.py results/AKCM-2026-0001  # kernel-check one result
.venv/bin/python scripts/pipeline.py --seed 20261124 --count 1 --offline   # generate without LLM credentials
.venv/bin/python scripts/bench_walk.py --label try --strict --only Filter  # benchmark one module (omit --only for all four)
.venv/bin/python scripts/calibrate_referees.py --out .tmp/calibration.json --offline   # plumbing check; live scores need the key, so run the Referee Calibration workflow
lake env lean scripts/calibration_set.lean > scripts/calibration_set.json   # rebuild the calibration set after a Mathlib bump
SITE_BASE_PATH="" .venv/bin/python scripts/build_site.py   # render _site/
python3 -m http.server -d _site 8000
```

The tests are plain assertion functions with no pytest dependency. A new `test_*` function only runs if it is also called in the `__main__` block of `scripts/test_akcm.py`.

Scripts import each other as flat modules (`from config import ROOT`), so run them as `python scripts/<name>.py` from the repository root. `python -m scripts.<name>` fails.

`pipeline.py` writes into `results/` and `state/`, which are committed data. After an experimental run, check `git status` and revert what you do not intend to publish.

Useful `pipeline.py` modes: `--wander --areas N` (specialist search across mutated Mathlib modules, what the nightly job runs; `--pool-factor` sets how many candidates are screened per published result, `--workers` how many walks run at once, and `--walk-timeout` how many seconds one walk may take, 240 by default), `--module M --focus F` (specialist search on one module), `--issue-only` (bundle unissued results into the next issue), `--publish-issue` (generate then bundle), `--launch-issue` (replace Issue 1). A launch can be given time: `--time-budget M` keeps generating for M minutes in rounds, each over a fresh set of `--areas` modules; `--screen-limit K` sends only K candidates of the pooled rounds to Referee A, each module's best by interest score before any module's second best (`selection.shortlist`); `--second-opinions N` has Referee B score Referee A's top N as well and ranks them by the mean of the two (`selection.second_opinion`), and that verdict is published as Referee B's report. `scripts/reeditorial.py --issue N` re-runs the editorial desk on existing results without touching the proofs.

`scripts/bench_walk.py` runs the specialist search on four fixed modules with two seeds each and writes a summary to `docs/superpowers/specs/bench/<label>.json`. Run it after any change to `Babel/`; `--strict` fails on a candidate that violates the non-triviality invariants. Wall time includes module loading, which varies a lot with the page cache, so compare the `search` phase when timing matters.

## Architecture

The flow is `lake exe walk` (Lean) → JSON candidates in `.tmp/` → referee screening and ranking → standalone kernel verification → editorial desk → `results/` and `state/` → static site.

### Lean generator (`Babel/`)

`Babel/Walk.lean` is the CLI entry point. It imports a module at runtime with `importModules` (default `Babel.Corpus`, a curated multi-domain import list; `--module` substitutes any Mathlib module whose olean exists), builds a lemma index, and runs walks until `--count` candidates pass the gates. The output file is one JSON object, `{"complete", "stats", "candidates"}`, rewritten atomically after every attempt, so a run killed by the pipeline's timeout still leaves its candidates and statistics. The pipeline kills the whole process group (`walk_runner.run_bounded`), because `lake exe` runs the walk binary as a child.

`Babel/Generator.lean` holds the search. Both strategies extend a derivation with `tryApplyLemma`:

- It unifies one explicit hypothesis of a lemma with an already derived fact, up to instance-reducible unfolding only. Default transparency would unfold `Set α` to `α → Prop` and derive statements nobody would write.
- Other premises are filled from other derived facts or local hypotheses. A proof fills at most one premise of an application.
- A premise nothing fills becomes a new variable or hypothesis of the theorem (`withOpenedBinders`), in telescope order. New type variables, and hypotheses that `simp` decides or shrinks, are refused, and a derivation may add at most `StepLimits.maxNewBinders` binders.
- The step is rejected when the lemma already occurs in its ancestry (`--max-lemma-repeats`, default 1), when the new fact exceeds `--max-statement-size` expression nodes, or when the new fact is padded (`isPaddedFact` in `Babel/Interest.lean`: `simp` proves it, shrinks it, or shrinks one of its explicit arguments, or it contains a set in unfolded form such as `fun x ↦ x ∈ s`). "Shrinks" is measured by `visibleSize`, which counts explicit arguments only: `simp` elaborates longer instance paths, so raw node counts would call a visibly smaller result larger.

`buildLemmaIndex` leaves out glue lemmas (`isGlueLemma`): those whose whole statement uses only logical, basic order and basic set vocabulary, such as `ne_of_eq_of_ne` or `Set.mem_of_eq_of_mem`. They add steps without mathematical content. Deprecated aliases are left out too, since an alias lets one lemma be applied twice under two names, and so are auto-generated `congr_simp` and `injEq` lemmas.

The two strategies differ in what they search for:

- **Default walk** (`runWalkLoop`): starts from a random seed theorem, opens its binders as local hypotheses, and chains lemmas found through `LemmaIndex.byHypHead`, sampling toward namespaces not yet used (`--interdisciplinary`). It stops at a random target length and gates that one derivation.
- **Specialist search** (`runSpecialistLoop`, enabled by `--focus`): seeds only from theorems defined under the focus module prefix and matches hypotheses through a `DiscrTree`. It spends `--trials-per-walk` lemma applications per walk and never runs a gate while searching. Every node whose derivation has at least `--min-proof-depth` retained steps, at least `--min-concepts` distinct concepts (the head constant of each step's statement), at least `--min-focus-steps` steps whose lemma is defined under the focus (the seed is one of them, so the default of 1 asks for nothing more), and a conclusion mentioning a symbol defined under the focus is closed over its hypotheses (`closeDerivation`). A closed statement with a dangling hypothesis is dropped there (`danglingHypotheses` in `Babel/Interest.lean`): a hypothesis that shares no visible variable with the conclusion, directly or through other hypotheses, such as `HasEval a` when `a` is printed nowhere else. The surviving derivation is offered to a small list of the best `--keep` derivations, ordered by `interestScore`, which rewards distinct concepts most, then the share of steps whose lemma is defined under the focus and length up to six steps, and penalises the readable size of the statement (`visibleSize`, explicit arguments only; the explicit node count is dominated by instance arguments). While a derivation is short of its on-topic steps, three extensions out of four draw from focus lemmas when the matching pool has any (`preferFocus`); without this steering a floor of 2 yields about half as many candidates. When the budget is spent, `runSingleWalk` gates that list best first.

`gateKept` is where a candidate is accepted or dropped, cheapest check first: duplicate statement, rendering, kernel check and axiom allowlist, then the novelty gate in `Babel/Gate.lean`. Level 1 is a hard gate: a statement closed by `exact?` is discarded. Level 2 (`simp` with the default simp set, or `aesop`, closes it) is a hard gate in specialist search and a badge in the default walk. Level 3 (proof size over statement size) is a badge. In specialist search a last gate asks the Level 1 question of every intermediate fact (`hasDefectiveShortcut`): when the derivation reached a fact in two or more lemma steps although the hypotheses give it by assumption or one library lemma, the shortcut is substituted into the proof, and the candidate is rejected (`shortcut`) if the shorter proof no longer uses some hypothesis or no longer uses any lemma of the focus area. A detour that only lengthens the proof is tolerated. On the twelve results of the first two live runs this rejects four that the other gates pass, each for the defect Referee B named.

`renderStandaloneClosed` prints the result as a self-contained file with minimal imports. It opens exactly the recorded number of hypothesis binders, so a conclusion that is itself a `∀` stays the conclusion, and it returns `none` when a printed term contains proof ellipses or hygienic names, since that text would fail to re-elaborate. In specialist mode the statement in `Result.lean` and `statement_lean` is printed fully explicit; `statement_pretty` is the readable form.

`Babel/Convolute.lean` has two independent inflation mechanisms. `convoluteExpr` wraps the kernel proof term and feeds the Level 3 ratio. `renderBaroqueTacticProof` generates the tactic-script ceremony ("Phase 1", "Phase 2", ...) that appears in the emitted `Result.lean`. Both use only core Lean lemmas so the axiom set is unchanged.

`Babel/Stats.lean` counts why applications and derivations were rejected and how long each phase took; the counts are in the output file and printed at exit. All randomness goes through the SplitMix64 `Rng` in `Babel/Util.lean`, threaded explicitly, and every budget is in heartbeats, so a given seed and toolchain reproduce the same walks on any machine.

### Python pipeline (`scripts/`)

`pipeline.py` orchestrates. It skips statement hashes already present in any `results/*/meta.json` (this is the real Level 0 check; the Lean side always reports `level_0_unseen: true`), renames the theorem from `akcm_candidate` to the ID-derived name, and re-verifies the standalone source with `verify.py` before anything is saved.

With `--wander` (and for the launch issue) the referee chooses what is published. `run_wander` runs the walks of all profiles in parallel (`walk_runner.run_walks_parallel`), asking for `pool_factor × count` candidates in total. `editorial.screen_candidate` has Referee A score every new candidate before any verification, since a referee call takes about a second and a standalone verification much longer. `selection.py` ranks the pool by that score and verifies down the ranking until `min(count, half the pool)` results pass, with at most two per module. The screening verdict is reused as Referee A's published report, so no result is scored twice by the same referee. Offline, without a key, or when a screening call fails, the generator's own `interest` score ranks the candidate instead and the record says so (`selection.source`). Referee-scored candidates always rank ahead of fallback-ranked ones, and after one failed call the referee is not asked again in that run.

`verify.py` copies the source into `.tmp/` with `#print axioms <name>` appended, runs `lake env lean` on it, and fails on a non-zero exit, on `sorry`, or on any axiom outside `propext`, `Classical.choice`, `Quot.sound`. The temp file has to live inside the workspace so Lake resolves Mathlib. This is the same check the Pages workflow runs before every deploy.

`wander.py` picks which Mathlib modules the specialist search visits. It scans the Mathlib sources under `.lake/packages/mathlib/` for theorem-rich modules, weights domains inversely to how often past results and `state/wander.json` have visited them (`explore`), and reserves one slot for a sibling module of a recently used focus (`drift`), preferring focuses whose candidates the referee scored highly. If the Mathlib checkout is absent, `pipeline.py` falls back to the hardcoded `LAUNCH_PROFILES`.

`editorial.py` runs the satire layer in `process_editorial`: two referees, then the namer, then the gloss. All of them read `statement_pretty` when the record has one. Referee A defaults to `gemini-decision-1` through the Gemini Decisions API (structured choice and score questions); any model whose name does not start with `gemini-decision-` goes through the OpenAI-compatible chat endpoint using `prompts/decider.md`. The namer (`prompts/namer.md`) is validated and retried up to four times: exactly one model family, or two when both referees score at least `joint_eponym_min_score`; no family matching `state/blocklist.json` (real AI models and real mathematicians, substring match included); press copy must contain "first" and "state of the art" and must omit the title. Model family versions and result counts persist in `state/families.json`; a family is retired after `deprecate_after` results, and every active family gets a minor version bump when an issue is published.

Every editorial step degrades to a deterministic offline heuristic. This happens with `--offline`, when no API key is found (`LLM_API_KEY`, then `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `OPENAI_API_KEY`, `GROQ_API_KEY`), and on any `LLMError`. A run therefore never fails because of the LLM, and a result whose referee `model` is `offline-heuristic-referee` was not reviewed live.

`calibrate_referees.py` measures the referees themselves. It has both score real Mathlib theorems through `run_decider` with the production personas, so the request is the one a generated result gets. The theorems are in `scripts/calibration_set.json`, built by `scripts/calibration_set.lean`: named theorems and trivial facts chosen by hand, and a seeded random sample from modules the search has explored, all printed like generated statements and with the lemma list of their real proofs. The journal's own results are scored again alongside. Referee B is asked several times per item because it answers at temperature 0.85. A failed call is recorded as an error; the script never substitutes the offline heuristic or another model.

`llm.py` is a `urllib`-only client, so there is no SDK dependency. Model and endpoint defaults come from `[llm]` in `akcm.toml` and can be overridden by environment variables read in `config.py` (`LLM_ENDPOINT`, `DECISIONS_ENDPOINT`, `DECIDER_1_MODEL`, `DECIDER_2_MODEL`, `NAMER_MODEL`, `GLOSS_MODEL`, plus `SITE_BASE_URL`, `SITE_BASE_PATH`, `SITE_CUSTOM_DOMAIN`, `SITE_REPO_URL`).

`build_site.py` renders `site/templates/` with Jinja2 into `_site/`: one page per issue grouped by two-digit MSC section, one page per result with an inline SVG of the lemma dependency DAG, the model-family leaderboard, retractions, about, and Atom feeds. When `state/calibration.json` exists it also renders the Referees page (`referees.html`), which shows what the two referees score real Mathlib theorems; the file is the output of a calibration run, copied from the workflow's artifact, and the reader-facing names of the classical theorems come from `label` in `scripts/calibration_set.json`. It deletes and rebuilds `_site/` on every run.

### Data model

Git is the database. `results/AKCM-YYYY-NNNN/` holds `Result.lean` and `meta.json`; `state/issues.json` lists which result IDs belong to which issue.

- `meta.json` `issue` is `null` for accepted results waiting for publication, a positive number once published, and `0` for the Prelaunch Archive. Issue 0 results keep their pages but are excluded from the leaderboard, the site-wide feed, and the archive totals.
- The displayed heading and press release are derived at render time by `render_editorial` from `title`, `proved_by`, and `press_release_body`. Older records store `eponym` and `press_release` directly, and `render_editorial` handles both shapes, so a title can be edited in `meta.json` without regenerating the rest.
- `run_launch` only writes results, issue state, and family state after the full requested count has been verified; a partial batch leaves the repository untouched and exits with status 1.
- On 2026-11-25 the thirteen results published until then were removed and the issue and family state reset, so that the launch issue starts the journal at `AKCM-2026-0001`. They remain in the git history, and their referee scores are on the Referees page (`state/calibration.json`). Because identifiers were reused, a calibration row is linked to a result page only while the ID still carries the statement that was scored.
- When Referee B took part in the selection, `selection.second_opinion` and `selection.combined` record its score and the mean; such a result's Referee B score was selected for, unlike the scores of earlier results.
- New results carry `interest` (the generator's score and its components), `checks` (`simp_normal`, `premise_reuse`, recomputed on the finished derivation), and `selection` (pool size, rank, ranking source, screening score). Older results have none of these.
- `state/candidates.jsonl` logs every screened candidate, published or not, with its interest components, screening score, and outcome, trimmed to the last 500 lines. It is the data for judging whether the interest score predicts the referee.
- `interest.statement_size` counts every expression node of the fully explicit statement, and `interest.readable_size` counts what a reader sees. Only the second enters the score. Results from before the readable size existed have no such field, and their scores used the first.
- `wander.py` gives each explored module an on-topic floor (`min_focus_steps`) of 1 or 2 at random. This is a running comparison: a floor of 2 answers Referee B's objection that the focus area is decoration, and it also empties some modules, so the exploration history is meant to show whether the referees prefer its results. Compare by `min_focus_steps` in `state/wander.json` and by `interest.focus_steps` in `state/candidates.jsonl` before making either value the rule.
- Entries in `state/wander.json` carry the pool size, number published, and best and mean referee score of each explored module; entries written before this existed, or by offline runs, have no score and get a neutral weight.

### CI

`nightly.yml` runs the generator every night (`--wander --areas 4`), publishes an issue on Sundays (`--issue-only`), and commits `results/` and `state/` straight to `main` as "AKCM Editorial Bot". Manual dispatch inputs select the launch issue or a re-editorial pass; for the launch issue, `launch_args` is appended to the pipeline command (for example `--time-budget 120 --areas 8 --screen-limit 120 --second-opinions 24`). The job may run for five hours (a hosted runner stops at six), and the repository is public, so Actions minutes are not billed. `pages.yml` runs on every push to `main` and after each successful nightly run: it verifies all results with the Lean kernel, then builds and deploys the site. Because the bot pushes to `main`, pull before starting local work. `calibrate.yml` (manual dispatch only) runs `calibrate_referees.py` with the live referees and commits nothing: the scores are in the job summary and in the `referee-calibration` artifact (`gh run download <run> -n referee-calibration`).

## Things that are easy to get wrong

- The Mathlib and Lean version is recorded in four places that have to move together: `lean-toolchain`, `lakefile.toml` (`rev`), and the hardcoded `"mathlib_rev": "v4.36.0"` in both `scripts/pipeline.py` and `scripts/build_site.py`. Existing results were verified against the old version and need `scripts/verify.py` rerun after a bump.
- The axiom allowlist is duplicated in `Babel/Util.lean` (`allowedAxioms`) and `scripts/verify.py` (`ALLOWED_AXIOMS`).
- A gate that throws answers "not closed", so a gate that always throws passes every statement. The `exact?` gate was in that state until 2026-11-25: `librarySearch` was called outside `goal.withContext` and threw on the first introduced hypothesis. Any Meta-level call on a goal after `intros` needs `goal.withContext` unless the function enters the context itself. `simp` and `aesop` throw when they make no progress, which is an ordinary failure and is caught inside their gates; any other failure is counted as `gate_error` in the statistics. A nonzero `gate_error`, or a gate with no rejections over a whole benchmark, deserves a look. `Babel/Tests.lean` checks that each gate closes one statement it should close.
- Setting the `maxHeartbeats` option does not limit anything inside the walk: the limit Lean enforces is `Core.Context.maxHeartbeats`, which the walk sets to unlimited. Use `withHeartbeatBudget` from `Babel/Util.lean` for any new check.
- A metavariable cannot be assigned, through `isDefEq`, a local variable declared after it; the scope check refuses and returns `false` without an error. `withOpenedBinders` assigns directly for that reason.
- The referees are the measuring instrument. Do not tune `prompts/decider.md`, the decision rubric, or the offline referee to raise scores.
- Result IDs are an in-house scheme (`AKCM-YYYY-NNNN`). The project deliberately never mints DOIs or arXiv-style identifiers, and invented model names must stay clear of real models and real mathematicians.
- While `custom_domain` is set in `akcm.toml`, `config.py` forces `base_url` to that domain and `base_path` to empty, so editing those two keys in the file has no effect. Only the `SITE_*` environment variables override them. In Actions, `GITHUB_REPOSITORY` changes `repo_url` only.
